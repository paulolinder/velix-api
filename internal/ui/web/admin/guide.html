1 Visão Geral

A Velix API é uma API REST que conecta seus sistemas ao WhatsApp multi-dispositivo sem navegador headless. Cada número do WhatsApp é representado por uma instância.

Fluxo básico

1Registrar workspace → obter JWT
2Criar instância → obter API Key da instância
3Conectar via QR Code ou Pairing Code
4Enviar e receber mensagens via API

A URL base da API é http://seu-servidor:8080/v1. Toda resposta segue o envelope {"success": true, "data": {...}}.

2 Autenticação

POST /v1/auth/register Primeiro acesso

Cria o workspace e o primeiro usuário admin. Disponível apenas até o primeiro workspace ser criado (single-tenant) ou quando REGISTRATION_ENABLED=true.

curl -X POST http://localhost:8080/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "workspace_name": "Minha Empresa",
    "slug": "minha-empresa",
    "email": "admin@empresa.com",
    "password": "Senha123!"
  }'

A resposta inclui um token JWT — guarde-o para as chamadas seguintes. A senha precisa ter pelo menos 8 caracteres, uma letra maiúscula, uma minúscula e um número.

POST /v1/auth/login 
curl -X POST http://localhost:8080/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "admin@empresa.com", "password": "Senha123!"}'

Usando o token nas chamadas

Inclua o JWT ou API Key no header Authorization:

Authorization: Bearer seu_token_aqui
# ou para API Keys:
X-API-Key: wapi_xxxxxxxxxxxxxxxxxxxxxxxx

API Keys por instância

Ao criar uma instância, uma API Key permanente é gerada automaticamente. Você pode criar chaves adicionais com escopos específicos:

POST /v1/auth/api-keys
{
  "name": "Integração n8n",
  "instance_id": "uuid-da-instancia"
}

Chaves com instance_id nunca expiram e só têm acesso àquela instância específica.

3 Criando e Conectando Instâncias

Uma instância representa um número do WhatsApp. Você pode ter várias instâncias por workspace (até o limite configurado em ENGINE_MAX_INSTANCES).

POST /v1/instances Criar instância 
curl -X POST http://localhost:8080/v1/instances \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "Atendimento"}'

A resposta inclui o id da instância e uma api_key gerada automaticamente — salve essa chave, ela só é mostrada uma vez.

Conectar via QR Code

Conecte a instância e então abra o stream SSE para receber o QR Code:

# 1. Iniciar conexão
POST /v1/instances/{id}/connect

# 2. Receber QR Code via Server-Sent Events
GET /v1/instances/{id}/qr
# (mantém a conexão aberta; events: "qr", "paired", "error")

# Cada evento "qr" traz:
# { "code": "...", "timeout_seconds": 60, "image": "data:image/png;base64,..." }

O campo image é um PNG em base64 pronto para exibir como <img src="...">. Escaneie com o WhatsApp no celular: Configurações → Aparelhos Conectados → Conectar Aparelho.

Conectar via Pairing Code (sem câmera)

# 1. Iniciar conexão
POST /v1/instances/{id}/connect

# 2. Solicitar código de 8 dígitos
POST /v1/instances/{id}/pair-code
{"phone": "5511999999999"}  # com código do país, sem +

# Resposta: {"code": "ABCD-1234"}

No celular: Configurações → Aparelhos Conectados → Conectar Aparelho → Conectar com número de telefone.

Estados da instância

disconnected — desconectado
connecting — aguardando QR
connected — online
banned — número banido

4 Enviando Mensagens

Todos os endpoints de mensagem ficam em /v1/instances/{instanceID}/messages/. O campo to aceita JID do WhatsApp no formato 5511999999999@s.whatsapp.net (pessoa) ou XXXXXXXXXXX-XXXXXXXXXX@g.us (grupo).

Texto simples
POST /v1/instances/{id}/messages/text
{
  "to": "5511999999999@s.whatsapp.net",
  "text": "Olá! Como posso ajudar?",
  "quoted_message_id": "MSGID123"  // opcional — responder mensagem
}
Mídia (imagem, vídeo, áudio, documento)
POST /v1/instances/{id}/messages/media
{
  "to": "5511999999999@s.whatsapp.net",
  "type": "image",          // image | video | audio | document | sticker
  "data": "<base64>",       // conteúdo do arquivo em base64
  "mime_type": "image/jpeg",
  "caption": "Veja isso!",  // opcional
  "file_name": "foto.jpg"   // opcional — para documentos
}
Envio em lote (até 100 destinatários)
POST /v1/instances/{id}/messages/batch
{
  "messages": [
    {"to": "5511111111111@s.whatsapp.net", "text": "Oi João!"},
    {"to": "5522222222222@s.whatsapp.net", "text": "Oi Maria!"}
  ]
}
// Resposta: array com status individual por mensagem (HTTP 207)
Agendamento

Inclua send_at em qualquer mensagem para agendá-la:

POST /v1/instances/{id}/messages/text
{
  "to": "5511999999999@s.whatsapp.net",
  "text": "Lembrete: reunião em 5 min!",
  "send_at": "2025-12-25T10:00:00Z"
}
// Resposta HTTP 202 — mensagem agendada

Gerencie mensagens agendadas em GET /v1/instances/{id}/messages/scheduled e cancele com DELETE /v1/instances/{id}/messages/{msgID}/schedule.

Enquete

POST .../messages/poll
{
  "to": "...",
  "question": "Qual horário?",
  "options": ["9h","14h","18h"],
  "multi_select": false
}

Reação

POST .../messages/reaction
{
  "to": "...",
  "message_id": "MSGID",
  "reaction": "👍"
}

5 Gerenciando Grupos

Endpoints em /v1/instances/{instanceID}/groups/.

# Listar grupos
GET /v1/instances/{id}/groups

# Criar grupo
POST /v1/instances/{id}/groups
{"name": "Equipe Vendas", "participants": ["5511111@s.whatsapp.net"]}

# Obter info de um grupo (incluindo JID para enviar mensagens)
GET /v1/instances/{id}/groups/{groupJID}

# Adicionar participantes
POST /v1/instances/{id}/groups/{groupJID}/participants
{"participants": ["5522222@s.whatsapp.net"], "action": "add"}
// action: "add" | "remove" | "promote" | "demote"

# Sair do grupo
DELETE /v1/instances/{id}/groups/{groupJID}

Para enviar mensagens a um grupo, use o JID do grupo (formato XXXXXXXXXX-XXXXXXXXXX@g.us) no campo to.

6 Webhooks

Configure uma URL de webhook nas configurações da instância para receber eventos em tempo real (mensagens recebidas, mudanças de status, etc.).

Configurar webhook
PATCH /v1/instances/{id}/settings
{
  "webhook_url": "https://meuservidor.com/webhook",
  "webhook_secret": "segredo-forte-123",
  "webhook_events": ["message.received", "instance.connected"]
  // Omita webhook_events para receber todos os eventos
}

Eventos disponíveis

message.received message.sent message.delivered message.read instance.connected instance.disconnected instance.qr call.received

Verificando a assinatura HMAC

Quando webhook_secret está configurado, cada requisição inclui o header X-Webhook-Signature: sha256=.... Verifique assim:

// Node.js
const crypto = require('crypto');
function verifySignature(body, secret, signature) {
  const expected = 'sha256=' + crypto
    .createHmac('sha256', secret)
    .update(body)
    .digest('hex');
  return crypto.timingSafeEqual(
    Buffer.from(signature), Buffer.from(expected)
  );
}

Payload de exemplo — mensagem recebida

{
  "event": "message.received",
  "instance_id": "uuid-da-instancia",
  "timestamp": "2025-01-15T14:30:00Z",
  "data": {
    "id": "MSGID123",
    "from": "5511999999999@s.whatsapp.net",
    "to":   "5511888888888@s.whatsapp.net",
    "text": "Olá, preciso de ajuda!",
    "timestamp": "2025-01-15T14:29:58Z"
  }
}

7 Integração com Chatwoot

O Chatwoot é uma plataforma open-source de atendimento ao cliente. A integração sincroniza mensagens do WhatsApp com conversas no Chatwoot automaticamente.

Passo 1 — Configurar no Chatwoot
1No Chatwoot, vá em Configurações → Inboxes → Nova Inbox
2Escolha o tipo API e nomeie a inbox (ex: "WhatsApp Vendas")
3Copie o Access Token, o Account ID e o Inbox ID
4Configure o webhook da inbox para https://seu-velix/v1/chatwoot/webhook?secret=SEU_SECRET
Passo 2 — Configurar na instância Velix
PATCH /v1/instances/{id}/settings
{
  "chatwoot_enabled":      true,
  "chatwoot_url":          "https://app.chatwoot.com",
  "chatwoot_token":        "access-token-do-chatwoot",
  "chatwoot_account_id":   "1",
  "chatwoot_inbox_id":     "5",
  "chatwoot_sign_msgs":    true,   // assinar mensagens saintes
  "chatwoot_reopen_conv":  true,   // reabrir conversa ao receber msg
  "chatwoot_conv_pending": false   // criar conversas como pendente
}
Passo 3 — Variável de ambiente no servidor Velix
CHATWOOT_WEBHOOK_SECRET=mesmo-secret-configurado-no-chatwoot

Sem essa variável o endpoint de webhook do Chatwoot retorna 503.

O que a integração faz automaticamente

  • ✓ Cria/reabre conversas no Chatwoot para cada contato que manda mensagem
  • ✓ Encaminha mensagens de agentes no Chatwoot para o WhatsApp
  • ✓ Sincroniza mídias (imagem, vídeo, áudio como nota de voz)
  • ✓ Sincroniza histórico de mensagens com POST /v1/instances/{id}/chatwoot/sync

8 WebSocket em Tempo Real

Conecte ao WebSocket para receber eventos de todas as instâncias do workspace em tempo real, sem polling.

// Conexão
ws://seu-servidor:8080/v1/ws?token=SEU_JWT

// Mensagens recebidas pelo cliente (JSON):
{
  "type": "message.received",
  "instance_id": "uuid",
  "data": { ... }  // mesmo payload dos webhooks
}

// JavaScript
const ws = new WebSocket(`ws://localhost:8080/v1/ws?token=${token}`);
ws.onmessage = (e) => {
  const evt = JSON.parse(e.data);
  console.log(evt.type, evt.data);
};

Use WebSocket para interfaces em tempo real (dashboards, atendimento ao vivo). Para integrações server-to-server, prefira webhooks — são mais confiáveis em caso de reconexão.
